# D5, D6 and D10 evidence checklist

- Compare SECURITY.md cadence and advisory source with every active updater entry and CODEOWNERS. The current updater is Dependabot; Renovate is inactive. If switching, disable Dependabot version updates and reconcile advisory source (OSV if using OSV) first.
- Run `gh api repos/jussray/aegis/vulnerability-alerts -i` and `gh api repos/jussray/aegis/automated-security-fixes -i` using owner-approved read credentials with the endpoint's required permissions. 204 confirms enabled; 404 can mean disabled or inaccessible, so independently confirm access. A 401/403, missing token or ambiguous 404 is UNVERIFIED, not proof disabled.
- Verify required CODEOWNERS review, protected tag rules and release environment reviewers in repository settings; a YAML environment name alone is not evidence. Owner must configure these before tagging. Do not bypass a failing check.
- Verify dependency advisory data with an actual dated source query. The configuration check is not an advisory scan.
- The release workflow creates a single source archive, same-run SBOMs, provenance and two SBOM attestations. Publication requires verifying the source ref, commit, signer and all three predicates; archive and SBOM assets are also hash checked. No container exists; image SBOM and OCI attestation are N/A for this repository. For a future image pipeline, stage by digest before attesting, authenticate registry access, and promote only the verified digest; never publish a mutable production tag before verification.
- Private-repository attestation requires an eligible GitHub plan. If unavailable, mark attestation capability N/A with evidence and hold publication; do not silently fall back to unsigned artifacts or change visibility.
- Record exact run ID, commit, tag, archive SHA-256, SBOM digests and verification outputs. The release verification job is the pre-publication guard; no separate privileged workflow_run job is needed.
- Post-release: download the archive, SBOMs and SHA256SUMS, verify hashes and all attestations (SECURITY.md). Confirm required assets and release tag. Record a dated receipt. A real rollback drill remains UNVERIFIED until an approved staging target and restored result exist.
- Never claim a control is VERIFIED solely because a file exists. No secret rotation, settings change, deployment or merge is authorized by these files.
